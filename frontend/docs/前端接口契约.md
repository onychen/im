# GoIM 前端接口契约（v1）

本文档以当前后端实现为准，供前端开发与联调使用。Swagger UI（`/swagger/index.html`）提供字段级参考；本文定义跨接口的一致规则和实时通信约定。

## 1. 基础约定

- HTTP 基地址：`/api/v1`；除 `POST /auth/*` 与 `GET /avatar/:userID` 外，均需 `Authorization: Bearer <accessToken>`。
- 请求与响应均为 UTF-8 JSON；上传头像为 `multipart/form-data`，字段名 `file`。
- 成功响应：`{ "code": 0, "message": "ok", "data": T }`；仅提示型成功响应可省略 `data`。
- 失败响应：`{ "code": 非0, "message": "..." }`。前端应优先使用 `code` 判断业务错误，`message` 仅用于展示。
- 列表响应的 `data` 固定为 `{ items: T[], pagination: { total, offset, limit, has_more } }`。
- `created_at`、`updated_at` 为 RFC 3339 UTC 字符串；消息 `timestamp`、`lastMsgTime` 为 Unix 毫秒。
- 消息相关字段（会话、seq、消息体）使用 camelCase，与 WebSocket 载荷一致。

### ID 规则

服务端资源 ID（包括评论 ID）由 MySQL 自增生成，前端以 JSON `number` 接收并原样回传；前端不得自行生成服务端资源 ID。消息由 `convId + seq` 唯一定位，`msgId` 为服务端全局 ID；客户端去重 ID 使用字符串 clientMsgId（发送时放在 `msgId` 字段）。

## 3. WebSocket

连接：`GET /ws?token=<accessToken>`。除 `kick` 外，消息统一为 `{ "type": string, "data": object }`。

客户端发送：`msg`、`readAck { convId, seq }`、`convSyncReq {}`、`pullMsgs { convId, fromSeq, toSeq }`、`revokeMsg { convId, seq }`。服务端发送：`msg`、`serverAck`、`convSync`、`pullMsgsResp`、`groupAdded`、`groupRemoved`、`error`、`kick`。撤回以 `msgType=6` 的 `msg` 下发。

关键流程：发送消息后等待 `serverAck`（表示已写入 Kafka），以 `clientMsgId` 关联临时消息并写入 seq；连接成功后发送 `convSyncReq`，对比每个会话的 `maxSeq` 与本地 `syncedSeq`，用 `pullMsgs` 按区间补拉，`hasMore=true` 时从 `toSeq+1` 继续；推送 seq 跳号时补拉空洞；收到 `kick`（载荷为 `{ type: "kick", reason: "new_login" }`）时清除本地登录态。

会话 ID：私聊为 `p_{较小用户ID}_{较大用户ID}`，群聊为 `g_{群组ID}`。详细帧定义与状态机见 `frontend/docs/WebSocket协议.md`，字段类型见 `frontend/goim-ws-types.ts`。

## 4. 前端错误处理

- HTTP 401 或 `code=1003/1106`：清除令牌并跳转登录。
- 修改用户名：`username` 必须为 3～50 个字符且全局唯一；冲突时返回 `409 / code=1103`。修改密码：必须提供当前密码，新密码至少 6 个字符；当前密码错误返回 `401 / code=1105`，前端应保留输入并展示错误。
- `code=4001~4003`：私聊发送失败（非好友、被拉黑、重复）；`5001~5002`：群聊发送失败（非成员、被禁言）。WS `error` 带 `clientMsgId` 时将该消息标记为失败并允许用同一 ID 重试。
- `code=1401/1402`：撤回失败（超过 2 分钟或非发送者）；`1404`：会话不存在。
- 请求超时、5xx、WebSocket 断线：保留用户输入或待发消息；重连后通过 `convSyncReq` + `pullMsgs` 修复状态，不要重复发送已收到 `serverAck` 的消息。
